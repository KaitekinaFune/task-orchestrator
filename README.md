# Taskroom / Task Orchestrator

Локальный дашборд задач для AI-агентов. Вы описываете задачу, а супервизор сам решает, каких агентов запустить и какие проверки провести, и спрашивает вас, только когда без этого нельзя. Код, состояние и журналы остаются локально; сами агенты обращаются к своим внешним API.

## Запуск

Нужны Node.js 22 или новее, Git и Bun; также нужен хотя бы один авторизованный CLI, Claude Code или Codex. Сервер работает на Node.js, а Bun управляет зависимостями и скриптами. В PowerShell из директории проекта:

```bash
bun install
```

```bash
bun run start
```

Откройте адрес, который напечатает сервер (по умолчанию `http://127.0.0.1:3000`). Порт задаёт `PORT`, каталог данных — `TASK_ORCHESTRATOR_DATA`. Скрипты Bun вызывают `node`, поэтому он должен быть в PATH.

## Как пользоваться

1. В «Проектах» подключите репозиторий. Подключайте только те, которым доверяете: агенты запускаются в них без отдельного подтверждения и могут загрузить их настройки, hooks и MCP.
2. На обзоре нажмите «Новая задача» (клавиша N), опишите её и нажмите «Поручить». Изображения можно вставить через Ctrl+V, перетащить или выбрать файл: PNG, JPEG, GIF или WebP до 3,75 МБ, не больше 5 за раз и 10 на задачу.
3. Следите за решениями супервизора и пишите ему в любой момент, в том числе с изображениями.

По умолчанию супервизор — Claude по подписке, воркеры — Claude и Codex. Изменить это можно в «Подключениях» → «Команда».

Необязательно: задайте команды проверок проекта, тогда супервизор сможет их запускать. Он не выполняет никаких других команд через оркестратор.

```json
[{ "id": "tests", "name": "Тесты", "executable": "bun", "args": ["run", "test"], "timeoutSeconds": 600 }]
```

Команды запускаются без shell; для PowerShell и `.bat` укажите `powershell.exe` с явными аргументами.

## Статусы

| Статус | Значение |
| --- | --- |
| в очереди | Директория занята другой задачей |
| выполнение | Работает супервизор, воркер или проверка |
| ждёт ответа | Супервизору нужен ваш ответ; процессов нет |
| готово | Супервизор завершил работу; проверки, если были, не провалены и относятся к текущим файлам. Это ещё не принятие результата |
| требуется решение | Супервизор не смог завершить, проверки провалены или устарели, либо исчерпан лимит |
| ошибка | Сбой CLI супервизора или сохранения; причина показана в задаче |
| прервана, отменена | Сервер перезапущен либо вы остановили задачу |

Продолжить можно из любого статуса, написав сообщение.

## Проверки проекта

```bash
bun run test
```

Тесты используют подставные процессы и не вызывают модели.

```bash
bun run smoke:supervisor
```

Сквозной запуск через настоящий сервер и Claude по подписке на временном репозитории. Расходует лимит модели: около цента на Haiku, которая используется в нём по умолчанию. Другая модель указывается аргументом при прямом запуске `node scripts/smoke-supervisor.mjs <модель>`.

```bash
bun run smoke:images
```

Отправляет настоящим Claude и Codex сгенерированные одноцветные картинки и проверяет, что модель называет цвет, в том числе при продолжении сессии и через сервер. Расходует лимит моделей. Только один агент: `node scripts/smoke-images.mjs claude`.
